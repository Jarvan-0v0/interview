Spring AI vs LangChain4j 高频

🎯 学习目标：掌握Spring AI的定位、核心概念（ChatClient/FunctionCallback/VectorStore/ETL Pipeline）、与langchain4j的全面对比（架构/API风格/生态/成熟度），能在面试中清晰回答"为什么选langchain4j不选Spring AI"以及"什么时候应该选Spring AI"。

Spring AI是Spring官方推出的AI框架，和langchain4j是Java生态的"双子星"——面试官问你"为什么选A不选B"，不是要你贬低另一个，而是考察你对技术选型的判断力。

1. Spring AI是什么 ★★★★☆

Spring AI是Spring团队在2024年推出的AI应用开发框架，旨在将AI能力像数据库访问、消息队列一样"Spring化"——用熟悉的Spring风格（注解、自动配置、Starter依赖）开发AI应用。

Spring AI的定位

Spring AI不是要"重新发明"AI框架，而是把AI能力融入Spring生态。它的设计哲学是：如果你会Spring Boot，你就会Spring AI。ChatClient就像RestTemplate，VectorStore就像JdbcTemplate，FunctionCallback就像@EventListener。

版本历程：2024年中0.8.x（里程碑版，API不稳）→ 2025年初1.0.0-M1 → 2025年下半年1.0.0正式版 → 2026年1.x持续迭代。当前（2026年中）已进入稳定期。

Spring AI之于AI开发 ≈ Spring Data之于数据库访问。Spring Data让你用@Repository注解操作MongoDB/Redis/MySQL，不需要写原生驱动代码。Spring AI让你用@Tool注解定义工具、用ChatClient调用LLM，不需要手写HTTP请求和JSON解析。

2. Spring AI核心概念速览 ★★★★☆

Spring AI 代码示例 
// 定义工具
@Component
public class OrderTools {
    @Tool(description = "查询订单状态（只读）")
    public OrderDTO queryOrder(
        @ToolParam(description = "订单号，如ORD12345") String orderId) {
        return orderService.findByOrderId(orderId);
    }
}

// 调用LLM（带工具）
@RestController
public class ChatController {
    private final ChatClient chatClient;

    public ChatController(ChatClient.Builder builder, OrderTools orderTools) {
        this.chatClient = builder
            .defaultSystem("你是客服助手，基于工具返回的信息回答")
            .defaultTools(orderTools)  // 注册工具
            .build();
    }

    @GetMapping("/chat")
    public String chat(@RequestParam String query) {
        return chatClient.prompt()
            .user(query)
            .call()
            .content();  // 同步调用
    }

    @GetMapping(value = "/chat/stream", produces = TEXT_EVENT_STREAM_VALUE)
    public Flux<String> chatStream(@RequestParam String query) {
        return chatClient.prompt()
            .user(query)
            .stream()
            .content();  // 流式调用，返回Flux<String>
    }
}

3. Spring AI vs LangChain4j 全面对比 ★★★★★ 必考

3.1 架构设计对比

对比维度LangChain4jSpring AI
设计哲学独立框架，模仿Python LangChainSpring原生，融入Spring生态
架构层次三层：应用层(@AiService) + 核心层(接口) + 集成层(模块)Spring Boot自动配置 + Starter依赖

3.3 关键差异：Agent能力

这是两框架最核心的差异

LangChain4j的AiServices：声明式Agent。定义接口+@AiService注解→框架自动生成实现类→LLM决定调用哪个@Tool方法→自动循环直到完成。一行代码一个Agent。

Spring AI的ChatClient：调用式Agent。ChatClient是调用入口，但你得自己写ReAct循环——调LLM→解析响应→判断是否需要工具→调用工具→把结果拼回Prompt→再调LLM。工具调用循环需要手动编排。

结论：如果要做复杂Agent（多工具+多轮循环），langchain4j的AiServices更省事。如果只是"调LLM回答问题"或"RAG检索+生成"，两者差别不大。但Spring AI可以手动实现ReAct循环（和mall-agent手写ReAct一样），控制粒度更细。

4. 选型建议：什么时候选哪个 ★★★★★ 必考

场景推荐理由
新项目，团队是Spring Boot技术栈Spring AISpring原生集成，自动配置，运维体系一致
需要复杂Agent（多工具+多轮循环）LangChain4jAiServices声明式Agent，开箱即用
需要快速原型验证LangChain4j社区示例多，集成模块丰富，上手快
企业级项目，需要长期维护Spring AISpring官方支持，版本稳定，长期可预期
已有langchain4j项目不迁移迁移成本高，ROI不划算。两个框架共存
需要可观测性开箱即用Spring AI内置Micrometer+OpenTelemetry，零配置
需要兼容非Spring项目LangChain4j不强制依赖Spring，纯Java也能用
需要对接Python生态LangChain4j与Python LangChain概念对齐，团队协作更顺畅
mall-agent选择langchain4j的原因：项目启动于2024年中，当时Spring AI还在0.8.x里程碑版本，API不稳定。langchain4j已经0.30+，有完整的Agent支持（AiServices）。如果现在（2026年）启动新项目，会重新评估Spring AI——它已经1.0+，成熟度大幅提升。

5. 迁移策略：langchain4j → Spring AI ★★★☆☆

如果团队决定从langchain4j迁移到Spring AI，需要评估迁移成本和收益。以下是指南：

迁移代价评估

  • @AiService → ChatClient + 手动循环：迁移量最大。AiServices的声明式Agent需要改为手动ReAct循环。如果项目已经手写ReAct（如mall-agent），迁移成本低——循环逻辑不变，只需换API调用方式。
  • @Tool → @Tool (Spring AI)：注解名相同但包不同，方法签名基本一致。迁移成本低，主要是改import。
  • ChatMemory → ChatMemory (Spring AI)：接口相似，迁移成本中等。
  • EmbeddingStore → VectorStore：抽象层不同，需要重写检索逻辑。迁移成本高。
  • RAG Pipeline → ETL Pipeline：文档加载/分块/向量化逻辑需重写。迁移成本高。

迁移建议：不要全量迁移。采用绞杀者模式——新功能用Spring AI写，旧功能保持langchain4j。两个框架可以在同一个Spring Boot项目中共存（依赖不冲突），通过配置切换。等langchain4j部分逐渐被替换完后，再移除依赖。

mall-agent的评估：当前深度绑定langchain4j的@AiService和ChatMemory，迁移成本>收益，不建议迁移。但新项目启动会优先考虑Spring AI。

6. 面试Q&A ★★★★★

为什么选langchain4j而不是Spring AI？

项目启动时（2024年中）Spring AI还在0.8.x里程碑版本，API不稳定，文档缺失严重。langchain4j已经0.30+版本，有完整的三层架构、声明式Agent（AiServices）、丰富的集成模块。从工程稳定性角度，选langchain4j是稳妥的选择。

现在Spring AI已经1.0+，成熟度大幅提升。但mall-agent已深度绑定langchain4j的AiServices、ChatMemory、StreamingChatModel等接口，迁移成本高，ROI不划算。新项目启动会重新评估——如果团队是纯Spring Boot技术栈，Spring AI是更自然的选择。

关键：说清楚"为什么当时选"和"现在怎么看"两个维度。展示你的技术判断有历史视角，不是"始终选一个"。
Spring AI和langchain4j的核心区别是什么？

核心区别三个：

1）设计哲学：langchain4j是独立框架（模仿Python LangChain），Spring AI是Spring原生（融入Spring生态）。Spring AI的ChatClient就像RestTemplate，VectorStore就像JdbcTemplate——Spring开发者零学习成本。

2）Agent能力：langchain4j的AiServices是声明式Agent——定义接口→框架自动生成实现→LLM决定调用工具→自动循环。Spring AI的ChatClient需要手动编排ReAct循环。做复杂Agent，langchain4j更省事。

3）可观测性：Spring AI内置Micrometer+OpenTelemetry，零配置。langchain4j需要手动集成Prometheus。

三个维度对比要清晰。说"Spring AI需要手动编排ReAct"是核心差异，展示你真的理解两个框架。
Spring AI的Advisors是什么？和langchain4j的ContentRetriever有什么区别？

Advisors是Spring AI的拦截器链机制，在LLM调用前后插入处理逻辑。类似Spring MVC的Interceptor。常见Advisor：

1）QuestionAnswerAdvisor：在调用前自动做RAG检索，把检索结果注入Prompt——等价于langchain4j的ContentRetriever。2）ChatMemoryAdvisor：管理对话历史，自动注入历史消息。3）SafeGuardAdvisor：过滤敏感内容。

核心区别：Advisors是更通用的AOP切面机制，不限于RAG——你可以自定义任何前置/后置处理。langchain4j的ContentRetriever只是RAG检索的专用接口。

"AOP切面"类比展示Spring思维。说"不限于RAG"展示你理解Advisors的通用性。
如果让你从零开始选，langchain4j还是Spring AI？

取决于三个因素：

1）团队技术栈：纯Spring Boot团队→Spring AI（零学习成本）；混合技术栈团队→langchain4j（不强制Spring依赖）。

2）项目复杂度：需要复杂Agent（多工具+多轮循环）→langchain4j（AiServices声明式）；简单RAG+问答→两者都可以，Spring AI更省事（自动配置）。

3）长期维护：企业级项目，需要5年+维护→Spring AI（官方支持，Spring生态长期稳定）；快速迭代的创业项目→langchain4j（社区活跃，更新快）。

如果是我现在启动新项目：纯Spring Boot团队+企业级项目→Spring AI。需要复杂Agent+快速验证→langchain4j。

三个因素（团队/复杂度/维护）的系统性思考展示架构判断力。不要只说"选X好"，要说"在什么条件下选X"。
  • Spring AI定位：Spring官方的AI框架，将AI能力Spring化——ChatClient如RestTemplate，VectorStore如JdbcTemplate
  • 核心差异：设计哲学（独立框架 vs Spring原生）+ Agent能力（AiServices声明式 vs ChatClient手动编排）+ 可观测性（手动 vs 内置）
  • Agent关键区别：langchain4j的AiServices自动生成Agent实现，Spring AI需手动写ReAct循环
  • 选型建议：纯Spring团队+企业级→Spring AI；复杂Agent+快速验证→langchain4j；已有项目→不迁移
  • 迁移策略：绞杀者模式，新功能用Spring AI，旧功能保持langchain4j，两个框架可共存
  • mall-agent选择：2024年启动，langchain4j更成熟。现在不迁移（成本>收益）。新项目会重新评估
  • 面试要点：说清"当时为什么选"+"现在怎么看"+"什么条件下选什么"三个维度
